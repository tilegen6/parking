# Contract: Recognition Event (cv → backend)

Единая, **вендор-нейтральная** форма события распознавания. Это шов между
любым источником распознавания и бэкендом.

- **Сегодня** источник = камера Hikvision (ANPR на борту), payload парсит
  `backend/src/hikvision.py`.
- **Завтра** источник = наша собственная CV-модель. Она обязана отдавать
  **ровно эту же форму** — тогда бэкенд менять не нужно.

Бэкенд не должен знать, кто распознал номер. Он знает только этот контракт.

## Где он реализован

| Сторона | Где |
|---------|-----|
| Приём | `POST /api/v1/hikvision/anpr-event` (`backend/src/modules/recognition.py`) |
| Хранение | модель `RecognitionEvent` (`backend/src/models.py`) |
| Внутренний DTO | `hikvision.ParsedEvent` → нормализуется в эти поля |

> ⚠️ Парсинг конкретного формата (Hikvision XML/multipart) — **деталь источника**,
> а не контракт. Контракт — это нормализованные поля ниже.

## Поля

| Поле | Тип | Обяз. | Описание |
|------|-----|:---:|----------|
| `plate_number` | string \| null | да | Номер. `null` если не распознан. |
| `direction` | enum | да | `ENTRY` \| `EXIT` \| `UNKNOWN` |
| `event_time` | string (ISO 8601 + TZ) | да | Момент проезда. Пример: `2026-06-13T10:15:32+05:00` |
| `confidence` | number 0..1 \| null | нет | Уверенность распознавания. |
| `camera_name` | string \| null | нет | Канал/имя/IP источника. |
| `source` | string | да | Кто распознал: `hikvision-anpr` \| `own-cv-v1` … |
| `photos` | object | нет | `{ "plate": url\|null, "vehicle": url\|null }` |
| `raw_ref` | string \| null | нет | Указатель на сырой payload (отладка). |

### Правила

- `direction` нормализуется на стороне источника (`forward→ENTRY`, `reverse→EXIT`,
  иначе `UNKNOWN`). Бэкенд получает уже готовый enum.
- `confidence` всегда 0..1 (Hikvision отдаёт 0..100 → делим на 100).
- `event_time` — со смещением таймзоны; без TZ трактуется как UTC.
- `source` обязателен, чтобы отличать события камеры от событий своей модели и
  вести их раздельно при миграции.

## Зачем это сейчас

Зафиксировав контракт до написания своей модели, мы получаем:
1. Замену движка распознавания без правок бэкенда.
2. Возможность гонять старую (камера) и новую (своя модель) распознавалки
   параллельно на одном бэкенде, сравнивая по `source`.
3. Чёткую зону ответственности: источник нормализует → бэкенд только сохраняет.
   Никакого второго парсера.
