# Camera Errors & Artifacts — список ошибок камеры

Закрывает задачу Integration #12. Часть пунктов уже подтверждена сообществом
(реальный тред по родственной модели), часть — под проверку на нашем железе.

## ✅ Подтверждённые грабли (из реальной практики)

- **Detection mode = только «Vehicle»** → номер приходит как `unknown`.
  Лечение: выставить **«License Plate & Vehicle»**.
- **ANR (дозапись) включён** → камера зацикливает первое событие, пока не
  получит `HTTP/1.1 200 OK`. Наш `capture_server.py` всегда отвечает 200; на
  отладке ANR лучше выключить.
- **Прилетает `TPSRealTime` вместо `ANPR`** — это счётчик трафика (JSON, без
  номера, `plateNo: unknown`). Фильтровать по `eventType == "ANPR"`.
- **Открытие шлагбаума с пульта не генерит ANPR-событие** — нужен отдельный
  alarm-input камеры, если такие проезды надо ловить.

## ⬜ Под проверку на нашей камере

### Распознавание
- [ ] Пустой `licensePlate` при наличии события.
- [ ] Подмена символов (O↔0, I↔1, латиница↔кириллица для региона).
- [ ] Низкий `confidenceLevel` ночью / в дождь / на встречном свете фар.

### Направление
- [ ] `direction` отсутствует/инвертирован относительно физического проезда.

### Дубли / тайминги
- [ ] Несколько событий на один проезд (медленный проезд, пробка).
- [ ] Сдвиг `dateTime` (рассинхрон NTP на камере).
- [ ] Таймзона: локальная (`+05:00`) vs UTC (`Z`).

### Транспорт / снимки
- [ ] Событие без вложенных JPEG (снимки выключены / не успели).
- [ ] Битый / обрезанный multipart.
- [ ] Имена частей отличаются от `licensePlatePicture/vehiclePicture/detectionPicture`.

> Каждый подтверждённый дефект: описание + пример из `captures/` + workaround
> на стороне backend.
