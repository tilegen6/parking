# Test Cases for Backend — handoff

Сценарии, которые backend обязан корректно отрабатывать (Session Service,
защита от дублей, расчёт длительности). Закрывает задачу Integration #11.

**Логика приведена к ТЗ «Smart Parking ANPR» v1.0** (§3.3, §4.2, §6.2). Где
поведение взято из ТЗ — указан источник.

## Статусы сессии (ТЗ §4.2)

`active` (на парковке) · `paid` (оплачено) · `unpaid` (выехал без оплаты) ·
`cancelled` (отменена админом) · `whitelist` (бесплатный въезд).
В MVP v1 (без оплаты) используются `active` (въезд) и `unpaid` (выезд).
`paid`/`whitelist` — с подключением оплаты/whitelist (v2).

## Гейт по confidence (ТЗ §2.4, §6.2)

`confidence < 0.85` или номер пустой → событие помечается `low_confidence`,
уходит в admin на ручную проверку, **сессия не создаётся**.

## Воспроизведение через replay.py

| Кейс | Команда |
|------|---------|
| TC-1 въезд→выезд | `python replay.py --scenario entry_exit` |
| TC-2 дубль на въезде | `python replay.py --scenario duplicate` |
| TC-3 повторный въезд | `python replay.py --scenario repeat_entry` |
| TC-4 выезд без въезда | `python replay.py --scenario exit_no_entry` |

## TC-1. Нормальный цикл
ENTRY(123ABC02, t0) → EXIT(123ABC02, t1)
Ожидание: одна сессия; въезд → `active`; выезд → `unpaid`,
`exit_time=t1`, `duration_seconds = t1 - t0`. (ТЗ §3.3)

## TC-2. Дубль на въезде (активная сессия уже есть)
ENTRY(123ABC02, t0) → ENTRY(123ABC02, t0+1s)
Ожидание: **новая сессия не создаётся, обновляется `last_seen`**; одна `active`.
(ТЗ §6.2: «Активная сессия уже есть (дубль) → не создавать новую, обновить last_seen»)

## TC-3. Повторный въезд без выезда (спустя часы)
ENTRY(123ABC02, t0) → ENTRY(123ABC02, t0+3ч)
Ожидание: то же правило — активная сессия есть → **обновить `last_seen`**, новую
не создавать. (ТЗ §6.2) Отдельное выявление «зависших» сессий — задача аналитики,
не дедупликации.

## TC-4. Выезд без активной сессии
EXIT(123ABC02) без открытой сессии
Ожидание: создать маркер **`event_without_session`** и уведомить admin; обычную
сессию не создавать. (ТЗ §6.2: «Машина выехала, сессия не найдена → создать
event_without_session, уведомить admin»)

## TC-5. Неуверенное распознавание
ENTRY(plate=null или confidence < 0.85)
Ожидание: событие → `low_confidence`, в admin на проверку; **сессия не создаётся**.
(ТЗ §2.4, §6.2)

## TC-6. Дубль на выезде
EXIT → EXIT той же машины
Ожидание: повтор в окне дедупликации игнорируется; сессия закрывается один раз
(`unpaid`), `last_seen` обновляется.
