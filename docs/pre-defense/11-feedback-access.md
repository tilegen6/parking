## Доступ

В момент проверки GitHub репозиторий private, default `main`; `tilegen6` имеет admin, `sabyrzzhan` и `kimbiled` — write. Дополнительные аккаунты руководителя/комиссии не предоставлены. Минимальное действие для доступа к private GitHub: руководитель создаёт аккаунт и сообщает login; комиссия предоставляет свои login. Затем владелец выдаёт минимально необходимые права и получатели принимают приглашения. Пароли и токены никому передавать не нужно.

Если руководитель использует только электронные документы, можно согласовать с ним экспорт комплекта и письменный отзыв через привычный канал. Это помогает рассмотрению, но **само по себе не выполняет** требование доступа к приватному репозиторию; способ доступа необходимо согласовать с комиссией. Репозиторий ради этого не делается публичным.

## Независимое командное ревью

Созданный draft PR — место для настоящих замечаний. Нурсултан или Акыл должен прочитать изменения, проверить ссылки/критерии/сценарии и оставить собственное ревью. Техническая авторизация их аккаунтов не используется для создания фиктивного одобрения. После исправлений reviewer подтверждает результат; только затем владелец может включить комплект в reviewed `main`.

Открытые внешние условия: подтверждение клиентской сводки; содержательный отзыв руководителя; доступ руководителю/комиссии; независимое ревью PR. Эти пункты требуют участия людей и не закрываются автоматически этим комплектом.
