# Четыре исправления перед защитой 21 октября

Версия — `pre-defense-1-r4`. Предыдущие теги не изменяются. Это исправления программных дефектов; согласование клиента, отзыв руководителя, доступ комиссии и фактический вклад участников по-прежнему подтверждаются людьми. YouTrack остаётся исключённым владельцем.

| Проблема | Исправление | Проверка |
|---|---|---|
| Тест даты зависел от текущего UTC-времени | Собственные фиксированные записи до/на/после границы суток; проверяются конкретные ID | `backend/tests/test_parking_api.py::test_filter_by_date`, оба контроля времени |
| Повреждённый JSON/XML записывался как событие | Синтаксис, поле номера, confidence, дата и multipart проверяются до записи события и фото; ответ 400 | `backend/tests/test_ingest_validation.py`; валидные JSON/XML/multipart проверены отдельно |
| Сессии читались анонимно | Все маршруты сессий и чтение журнала требуют действующего JWT активного пользователя; отмена/назначение направления — operator/admin, с аудитом | `backend/tests/test_session_auth.py`, тесты логина/ролей и прежние сценарии с настоящим тестовым JWT |
| Расширенный KZ-модуль не участвовал в распознавании | `Pipeline` вызывает `normalize_kz`; FastPlate/template сохраняют посимвольные confidence; image/video/stream сохраняют решение выбранного чтения; raw/status передаются backend | `cv/tests/test_kz_integration.py`, `test_service.py`, контракт и backend-пробы |

В backend `ambiguous`/`unknown_format` сохраняются как событие для разбора без создания парковочной сессии. Исходная confidence не подменяется нулём; сырой OCR доступен в `plate_raw`, причина в `raw_payload`. Назначение направления не снимает отказ нормализации. Новые поля контракта необязательны: прежние корректные payload камеры сохраняют совместимость.

Разделение ролей в этих изменениях: admin/operator/list_manager могут читать сессии и журнал; operator/admin могут отменять сессию и назначать направление; list_manager эти изменения выполнять не может. Пароль и токен в документы не помещаются. Frontend уже отправляет Bearer из выполненного входа, поэтому новый отдельный вход для сессий не нужен.

EasyOCR этим адаптером не предоставляет уверенность по каждому символу; правила работают с доступной информацией, а их реальную точность ещё требуется измерить. Шаблонный тест не является обучением модели. Правильный формат, высокий confidence и прохождение unit-тестов не доказывают правильность номера на парковке.

Повторный полный набор: **158 backend +103 CV =261 tests passed**; lint/format/mypy и frontend build пройдены. Подробности — [протокол](12-verification-results.md), [машиночитаемая сводка r4](verification-results-r4.json). Docker startup, PostgreSQL-конкуренция, настоящий Kaspi, физический барьер и restore этим прогоном не подтверждаются. Авторизация остальных API и доверие к устройствам требуют отдельной проверки до внешнего пилота.

Для выступления: объяснить четыре причины и показать один регрессионный тест; затем обычный путь «номер → событие → сессия → тариф → подтверждение оплаты → решение о выезде». Автономный [макет](prototype/index.html) показывает синтетические сценарии, не совершает платежей и не открывает реальный шлагбаум. Новые полевые показатели не заявляются.
